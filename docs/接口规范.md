# 接口规范 v0.2（草案）

> v0.2 相对 v0.1 的变化：`if` 的 `value` 改为可选；新增**控制线**（只决定节点跑不跑，不传数据，见 5.6）；新增模块 `text.format`（把值转成文字）与 `text.join`（把列表合成文字）。v0.1 的图在 v0.2 下仍然有效，`spec` 写 `"0.1"` 或 `"0.2"` 均可。

本规范定义三件事：**模块怎么描述**、**工作流图怎么表示**、**图怎么运行**。
执行引擎、AI 生成图、前端编辑都以本规范为唯一依据。改动本规范需要同步更新 `schemas/` 与 `tools/validate.py`。

---

## 1. 基本概念

| 概念 | 含义 |
|---|---|
| 模块（module） | 预先写好、测试过的一个能力，例如抓取网页、调用大模型思考。内部是普通代码，图上不编辑其内部。 |
| 节点（node） | 图上的一个方块。可以是一个模块的实例，也可以是流程控制（分支、循环、合并）或子图。 |
| 端口（port） | 节点的输入口和输出口，每个端口有名字和类型。 |
| 连线（edge） | 数据线：从一个节点的输出端口到另一个节点的输入端口，表示数据传递。控制线：从 `if` 的 `then`/`else` 指向一个节点（不写端口），只决定该节点是否运行。 |
| 工作流（workflow） | 一张完整的图，有自己的输入和输出，本身也可以作为子图被别的工作流使用。 |

**原则：程序就是这张图。** 拖动、连线、替换节点就是在修改程序。模块内部的代码不出现在图上，因此不存在“图和代码双向同步”的问题。

## 2. 类型

端口类型只有以下几种，保持少而稳定：

| 类型 | 说明 |
|---|---|
| `string` | 文本 |
| `number` | 数字（含小数） |
| `integer` | 整数 |
| `boolean` | 真 / 假 |
| `object` | 任意 JSON 对象 |
| `file` | 本地文件路径（字符串形式，运行时检查文件存在） |
| `list<T>` | 由类型 T 组成的列表，例如 `list<string>` |
| `any` | 任意类型；只在确实无法确定时使用 |

**连线兼容规则**（校验器执行）：

- 类型完全相同 → 可以连。
- 任一端是 `any` → 可以连。
- `integer` → `number` → 可以连（反过来不行）。
- `list<A>` → `list<B>` 按 A → B 的规则判断。
- 其余一律不可以连，必须经过一个转换模块。**不允许在连线上做隐式转换。**

## 3. 模块描述（`modules/<模块名>/module.json`）

每个模块一个目录，包含 `module.json`（描述）、`module.py`（实现）、`test_module.py`（测试）。下面是简化示例，完整写法见 `modules/web_fetch/module.json`。

```json
{
  "id": "web.fetch",
  "version": "0.1.0",
  "name": "抓取网页",
  "description": "下载一个网址的内容，返回正文文本和状态码。",
  "category": "获取",
  "side_effects": "network",
  "inputs": {
    "url":       { "type": "string",  "required": true,  "description": "要抓取的网址，必须以 http:// 或 https:// 开头" },
    "timeout_s": { "type": "number",  "required": false, "default": 15, "description": "超时秒数" }
  },
  "outputs": {
    "text":   { "type": "string",  "description": "返回内容的文本" },
    "status": { "type": "integer", "description": "HTTP 状态码" }
  },
  "errors": [
    { "code": "invalid_url", "when": "网址格式不对" },
    { "code": "timeout",     "when": "超过 timeout_s 仍无响应" }
  ],
  "examples": [
    { "title": "抓取示例页面",
      "input":  { "url": "https://example.com" },
      "output": { "status": 200, "text": "<!doctype html>…Example Domain…" } }
  ],
  "runtime": { "entry": "module.py:run", "timeout_s": 60 }
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 全局唯一，格式 `类别.名称`，只用小写字母、数字、下划线和点 |
| `version` | 是 | 语义化版本。改变输入输出含义时升主版本号 |
| `name` / `description` | 是 | 给人和 AI 看的说明。**AI 依据这里选择模块，要写清楚能做什么、不能做什么** |
| `category` | 是 | 前端分组用：获取、思考、处理、逻辑、输出 等 |
| `side_effects` | 是 | `none` / `read`（读本地文件）/ `network` / `write`（写文件或产生外部影响）。执行引擎据此决定是否需要用户确认 |
| `interaction` | 否 | 写 `ask` 表示这个模块会停下来问使用者：引擎先发 `ask` 事件（带除 `answer` 外的全部参数），界面弹出提示窗，回答通过 `POST /api/run/{run_id}/answer` 送回、填进 `answer` 输入后再运行模块。模块须声明 `answer` 输入（`object`，默认 `{}`）并在没有回答时给出默认行为（命令行、运行检查里没人可问） |
| `inputs` / `outputs` | 是 | 端口定义，见下 |
| `errors` | 否 | 可能的错误代码和触发条件 |
| `examples` | 是 | **至少一个**。给 AI 理解模块的作用，也是测试用例的来源。较长输出可用 `…` 省略 |
| `runtime.entry` | 是 | `文件:函数`。函数签名为 `run(inputs: dict) -> dict` |
| `runtime.timeout_s` | 是 | 引擎强制的单次执行上限 |
| `runtime.dry_run` | 否 | 只用于 `side_effects` 为 `write` 的模块：`文件:函数`，签名与 `run` 相同。演练时照常检查参数、返回与真实运行相同形状的结果，但不改动任何东西。生成时的运行检查用它代替真实运行 |

端口字段：`type`（必填）、`description`（必填）、`label`（可选，2–4 个字的中文短名，画布上插孔旁显示的就是它，如“网址”“状态码”；不写时显示类型的中文词）、`required`（仅输入，默认 `true`）、`default`（仅输入，可选）。

### 模块实现约定

- `run(inputs)` 收到的字典已由引擎补齐默认值并检查过类型。
- 正常时返回一个字典，键必须与 `outputs` 完全对应。
- 出错时抛出 `ModuleError(code, message)`，`code` 应在 `errors` 中列出。
- 模块之间不互相调用；组合只发生在图上。

## 4. 工作流图（`*.workflow.json`）

```json
{
  "spec": "0.2",
  "id": "summarize_page",
  "name": "抓取网页并总结",
  "intent": "给我一个网址，输出这个网页的三句话中文总结",
  "inputs":  { "url":     { "type": "string", "description": "网址" } },
  "outputs": { "summary": { "type": "string", "description": "总结" } },
  "nodes": [
    { "id": "fetch",  "kind": "module", "module": "web.fetch@0" },
    { "id": "think",  "kind": "module", "module": "llm.think@0",
      "config": { "instruction": "用三句话中文总结以下网页内容" } }
  ],
  "edges": [
    { "from": "$in.url",     "to": "fetch.url" },
    { "from": "fetch.text",  "to": "think.text" },
    { "from": "think.answer","to": "$out.summary" }
  ],
  "layout": { "fetch": { "x": 0, "y": 0 }, "think": { "x": 240, "y": 0 } }
}
```

| 字段 | 说明 |
|---|---|
| `spec` | 本规范版本：`"0.2"`（`"0.1"` 仍可用） |
| `intent` | 用户最初的自然语言需求，原文保留 |
| `inputs` / `outputs` | 工作流整体的输入输出端口，格式同模块端口 |
| `nodes` | 节点列表，见第 5 节 |
| `edges` | 连线。端点写作 `节点id.端口名`；工作流自身的输入输出写作 `$in.名字`、`$out.名字` |
| `layout` | 只用于前端显示位置，**不影响运行**。可以省略，由前端自动排版。循环、子流程的 `body` 里也可以有自己的 `layout`（坐标相对于循环框内部）；在画布上编辑后会写入 |

**`config`**：给节点的输入端口直接设固定值，例如给“思考”节点写死提示词。同一个输入端口不能既有 `config` 又有连线。

**模块引用** `web.fetch@0` 表示该模块的主版本 0。主版本号变化时，旧图不会被自动套用到新版本。

## 5. 节点种类

### 5.1 `module` —— 模块实例
端口来自模块描述。

### 5.2 `if` —— 条件分支
| 端口 | 方向 | 类型 |
|---|---|---|
| `condition` | 输入 | `boolean`（必需） |
| `value` | 输入 | 任意（由连线决定）；**可选** |
| `then` | 输出 | 与 `value` 相同 |
| `else` | 输出 | 与 `value` 相同 |

`condition` 为真时走 `then`，否则走 `else`。没被选中的那一侧，下游节点整体**跳过**。
比较、判断语言等逻辑由模块完成（例如 `logic.compare`），`if` 节点本身不写表达式。

两种用法：
- **带 `value`**：要往下传的数据从被选中的一侧流出，`then`/`else` 可以接数据线，也可以接控制线。
- **不带 `value`（只做路由）**：分支里没有数据可传，例如“分数及格就写祝贺、否则写鼓励”。此时 `then`/`else` **只能接控制线**（5.6）。

### 5.3 `merge` —— 合并分支
| 端口 | 方向 | 类型 |
|---|---|---|
| `a`, `b` | 输入 | 同一类型 |
| `value` | 输出 | 同上 |

默认两个输入 `a`、`b`；需要更多时写 `"ports": ["a", "b", "c"]`。输出第一个**实际到达**的输入。用于把 `if` 的两条支路重新汇合。如果所有输入都被跳过，`merge` 也被跳过。

### 5.4 `foreach` —— 循环
```json
{ "id": "each", "kind": "foreach", "max_items": 100,
  "body": { "inputs":  { "item":   { "type": "string" } },
            "outputs": { "result": { "type": "string" } },
            "nodes": [ … ], "edges": [ … ] } }
```
| 端口 | 方向 | 类型 |
|---|---|---|
| `items` | 输入 | `list<T>` |
| `results` | 输出 | `list<U>` |

对 `items` 的每一项运行一次 `body`，`body` 内用 `$in.item` 取当前项、写入 `$out.result`，所有结果按原顺序组成 `results`。
`max_items` 必填，超过即报错，防止失控。v0.2 只支持“对每一项”这一种循环；条件循环（while）等真实需要出现再加。

### 5.5 `subflow` —— 子图
```json
{ "id": "clean", "kind": "subflow", "ref": "subflows/clean_text.workflow.json" }
```
或直接内嵌 `"body": { … }`（结构同 `foreach.body`）。子图的端口就是被引用工作流的 `inputs` / `outputs`。
**前端把子图显示为一个可展开的大节点**，这是控制图纸大小的主要手段。

### 5.6 控制线（v0.2 新增）
```json
{ "from": "branch.then", "to": "congratulate" }
```
`to` 只写节点 id、不写端口，就是控制线。它不传任何数据，只表示：**`branch.then` 被选中时，`congratulate` 才运行；没被选中，`congratulate` 跳过**。

- 控制线的起点只能是 `if` 节点的 `then` 或 `else`。
- 终点可以是同一层图里的任意节点（模块、`if`、`merge`、`foreach`、`subflow`）。
- 一个节点可以有多条控制线，**全部**被选中时才运行。
- 控制线同样不能形成环。

完整例子（v0.1 无法表达的“按分数写一句话”）：
```json
"nodes": [
  { "id": "passed", "kind": "module", "module": "logic.compare@0", "config": { "op": "ge", "b": 60 } },
  { "id": "branch", "kind": "if" },
  { "id": "score_text", "kind": "module", "module": "text.format@0", "config": { "template": "分数：{value}" } },
  { "id": "congratulate", "kind": "module", "module": "llm.think@0", "config": { "instruction": "写一句祝贺的话" } },
  { "id": "encourage", "kind": "module", "module": "llm.think@0", "config": { "instruction": "写一句鼓励的话" } },
  { "id": "join", "kind": "merge" }
],
"edges": [
  { "from": "$in.score", "to": "passed.a" },
  { "from": "passed.result", "to": "branch.condition" },
  { "from": "branch.then", "to": "congratulate" },
  { "from": "branch.else", "to": "encourage" },
  { "from": "$in.score", "to": "score_text.value" },
  { "from": "score_text.text", "to": "congratulate.text" },
  { "from": "score_text.text", "to": "encourage.text" },
  { "from": "congratulate.answer", "to": "join.a" },
  { "from": "encourage.answer", "to": "join.b" },
  { "from": "join.value", "to": "$out.message" }
]
```

## 6. 运行语义（执行引擎实现依据）

1. **数据驱动**：一个节点的所有必需输入都就绪后才运行；互不依赖的节点可以并行。
2. **无环**：普通连线不能形成环。重复执行只能通过 `foreach`。
3. **跳过传播**：节点的任一已连接输入来自被跳过的节点，或任一控制线的起点没被选中，则该节点跳过（`merge` 例外：只有全部输入都被跳过才跳过）。被跳过的节点，其所有输出也视为被跳过。
4. **出错即停**：任何节点出错，整个运行停止，报告出错节点、错误代码和已有结果。v0.2 不做自动重试。
5. **超时**：每个模块受 `runtime.timeout_s` 限制。
6. **副作用确认**：`side_effects` 为 `write` 的模块，首次运行前需要用户确认（网页上每次运行前弹窗确认，要确认的模块由 `POST /api/writes` 事先找出，包括引用的子流程里的；命令行逐个询问）。生成时的运行检查不询问：有 `runtime.dry_run` 的模块改为演练（同样在独立进程里运行），没有的一律拒绝。
7. **运行记录**：保存每个节点的输入、输出、耗时和状态（完成 / 跳过 / 出错），供前端在图上显示。

## 7. 校验规则（`tools/validate.py` 执行）

一张图在运行或交给前端之前必须通过：

1. 结构符合 `schemas/workflow.schema.json`。
2. 节点 `id` 唯一；连线引用的节点和端口都存在。
3. 引用的模块存在，主版本匹配。
4. 每个必需输入恰好有一个来源（连线、`config` 或默认值）；一个输入端口最多一条连线。
5. 连线两端类型兼容（第 2 节）。
6. 数据线与控制线合起来无环。
7. 工作流的每个 `$out` 都有来源。
8. `foreach` 有 `max_items`；`body` 递归满足以上全部规则。
9. 控制线的起点必须是 `if` 的 `then`/`else`，终点必须是同层存在的节点；不带 `value` 的 `if`，其 `then`/`else` 不能接数据线。

AI 生成的图如果没通过，校验器给出的错误信息会原样反馈给 AI 让它修正。

## 8. 暂不包含（等真实需要出现再加）

条件循环、自动重试、长时间运行的异步任务、多人协作、权限体系。
